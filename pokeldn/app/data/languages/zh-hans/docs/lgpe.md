# Let's Go! 皮卡丘和伊布

在宝可梦 Let's Go! 皮卡丘和 Let's Go! 伊布（2018）中，Pia 静态链接到`main` (269 `nn::pia`个类出现在 RTTI 中），游戏的 C++ 代码在其上通过以下组件使用协议缓冲区消息：`gflnet3`，这也是一年后剑和盾使用的中间件。

静态分析使用 Let's Go! 皮卡丘 1.0.2（`010003f003a34000`，更新 NSP 为`v131072`，SDK 5.4.151.0）；硬件测量使用法语版 Let's Go! 皮卡丘和一份 Let's Go! 伊布。Let's Go! 伊布使用皮卡丘版的本地通信 ID，因此两种角色均无需修改就能与伊布版交换。

本地交换和对战要求双方玩家输入连接密码：从固定的十种宝可梦中按顺序选择三只，选项分两行显示：皮卡丘、伊布、妙蛙种子、小火龙、杰尼龟；波波、绿毛虫、小拉达、胖丁、地鼠。密码用于设置广播通告的场景 ID（[会话页面](lgpe_session.md#the-link-code)）；任意密码都支持作为主机端和加入端运行。

## 已实现的功能

`bin/lgpe_join.py`加入主机会话，而`bin/lgpe_host.py`创建供主机加入的会话。一个席位支持连续交换：每次交换正常保存后，交换分发器会从状态 7 返回状态 1，除非保存过程报告连接结束（`0x886908`），并且保存过程会在新通道上重新创建同行宝可梦提供对象（`0x8375a4`) ([会话页面](lgpe_session.md#the-trade-dispatcher)）。两个启动器均接受记录队列，在同一席位每次交换使用一条记录。游戏不会检查接收的盒装结构中的任何字段：一只 100 级异色、变身者特性的百变怪，所有个体值为 31、所有觉醒值为 200，均可在概况界面读回。克隆协议的接管交换会通过游戏的`0x11b080`门控，可靠协议则承载身份、提供记录、提交和类型 4（下一次交换的选择）；`pokeldn.lgpe.pb7`读写提供记录和类型 4 携带的 232 字节盒装结构。

两种角色均可在同一席位完成队列中的三次交换。每个已完成条目保存为带校验和的 260 字节文件，主机离开后，主机端以退出码 0 结束。由`pokeldn.pokemon`生成（已指定等级、性别、性格、精灵球、个体值和觉醒值），并通过`bin/lgpe_host.py --fresh-pid`提供的记录，其各字段会显示在接收方的概况界面中。

玩家按下 Retour（返回）时，主机会离开席位。`bin/lgpe_join.py --leave-after SECONDS`会在首次应答交换步骤后经过指定时长时执行相同的退出操作，而`bin/lgpe_host.py`会响应主机的 Retour（返回）操作（[加入端离开](lgpe_session.md#a-joiner-leaving)). `tests/test_lgpe_host_commit.py`通过脚本模拟的主机固定验证主机端的提交阶段：错误的提交会使主机停留在确认界面，并设置存档的交换锁（累计游玩时间十分钟内无法交换），之后进入致命错误界面。
