# 代码组织

GUI 和 CLI 共享工具预设与宝可梦准备逻辑。游戏模块保留其经测量确认的协议传输格式和时序；共享组件应放在游戏目录之外。

| 位置 | 职责 |
| --- | --- |
| `pokeldn/app/` | 工具目录、参数组装、解析器检查、设置、路径和子进程 |
| `pokeldn/popup.py` | [弹窗](gui.md#pop-ups)由程序在应用中显示；`pokeldn/app/popups.py`决定显示哪些弹窗 |
| `pokeldn/pokemon.py` | PKHeX 服务、导入、最终交换宝可梦验证以及接收的文件 |
| `pokeldn/gifts.py` | 共享的[神秘礼物文件](gifts.md)封装、读取器、写入器及原生格式转换 |
| `pokeldn/receiver_gift.py` | 交换主机端针对主机存档生成的神秘礼物宝可梦（[为接收玩家生成](gift_simulated.md#made-for-the-receiving-player)) |
| `services/pkhex/` | 固定版本的 PKHeX.Core 依赖；合法遭遇生成与游戏兼容性检查 |
| `pokeldn/ldn/` | 无线传输、IP、Pia、可靠性及信道表 |
| `pokeldn/online/` | [在线交换](online.md)：中继、匹配及加密的伙伴通信通道 |
| `pokeldn/gba/` | GBA 无线连接协议 |
| `pokeldn/gen8.py`, `pokeldn/gen9.py` | 共享的宝可梦记录编解码器 |
| `pokeldn//` | 游戏身份、消息、状态机及协议特有差异 |
| `bin/` | 解析器与会话编排 |
| `gui/` | 视图、控件、主题和开发板控制 |

FRLG 配置档、广播通告和礼物设置位于`pokeldn/frlg/`。旧版配置和编解码器导入路径保留了小型兼容适配层。

由于一块开发板只能服务一个进程，应用一次只运行一个会话。仅正在运行会话的工具显示“停止”；在另一工具中点击“开始”会停止该会话，等待其退出，然后再启动。刷写固件也会占用开发板，“开始”会等待刷写完成。

## 宝可梦准备

共享服务生成合法遭遇，并将导入内容保存为所选游戏的格式。每个交换启动器都会先准备用户提供的文件，再启用无线收发器。应用编辑或按要求生成全新身份后，会对结果进行检查。不兼容的格式、不可用的种类以及不合法的最终记录都会被拒绝。会话的训练家身份不会覆盖导入宝可梦的初训家。

PKHeX 的`LegalityAnalysis.Parsed`记录分析是否完成。辅助程序将其返回为`parsed`。如果一次检查返回`parsed: false`，则重启辅助程序，并将同一请求重试一次；若第二次分析仍不完整，则引发验证器错误。已完成检查但被判定不合格的记录仍会被拒绝。服务锁覆盖首次检查、重启和重试的全过程。

修改 PID 和加密常量可能破坏遭遇相关性，尤其是活动和团体战遭遇。全新身份需要主动启用，且必须通过 PKHeX 检查；活动固定训练家会被保留。若记录原本合法，但换用全新身份后不合法，则保留原有 PID 和加密常量，启动器会记录`the offer kept its own PID`。生成时会先尝试该种类的所有其他遭遇，最后才尝试神秘礼物遭遇，因此有野生、定点或蛋遭遇的种类绝不会以活动宝可梦的形式生成。

生成的宝可梦由遭遇转换为记录而来。异色要求会传给遭遇，因此第三世代 PID 能保持 PKHeX 所要求的随机数关联。仅有一种性别的种类会向遭遇请求该性别：仅限雌性的蜂女王或雪妖女只能来自雌性三蜜蜂或雪童子。PID、个体值，以及野生遭遇槽位的等级，均随机抽取，因此每个遭遇最多尝试八次，之后才会跳过。若目标种类由遭遇进化而来，且没有任何遭遇能以捕获时的状态满足要求，则将其提升到进化等级。当进化后种类无性别时，记录采用进化后种类的性别（土居忍士进化为脱壳忍者）；当进化后种类没有原遭遇的形态时，则采用形态 0（伽勒尔大葱鸭进化为葱游兵）。

PKHeX 无法满足的请求会被拒绝，并说明原因。若等级低于最低遭遇等级，会报告该等级；若请求异色，但全部遭遇均锁定非异色，会说明这一点；若该种类在游戏中没有遭遇，也会说明。固定等级的礼物和仅限活动的种类没有更低等级的形式。对每款游戏的每个种类遍历六种请求形式（普通、异色、50 级、100 级、50 级异色、昵称）后，普通生成失败的情况如下：

| --- | --- | --- |
| 火红／叶绿 | 386 | 0 |
| Let's Go | 153 | 0 |
| 传说 阿尔宙斯 | 226 | 0 |
| 晶灿钻石／明亮珍珠 | 493 | 2 |
| 剑／盾 | 664 | 3 |
| 传说 Z-A | 364 | 5 |

### 交换宝可梦选项

生成时还可以指定形态、性格、特性、性别、携带物品、精灵球、亲密度、最多四个招式、个体值和努力值。招式和形态会将遭遇搜索范围缩小到能够包含它们的遭遇。性格、特性、性别和个体值会写入遭遇条件，使生成的记录具有这些属性；第三世代会搜索满足所请求性格的 PID。当遭遇随机生成的结果不同于要求时，会按照玩家在游戏中可执行的方式调整记录，再由合法性分析判断结果：

| 不同之处 | 调整方式 |
| --- | --- |
| 性格 | 从第八世代起，用薄荷设置能力值所采用的性格 |
| 特性 | 切换到具有该特性的槽位（特性胶囊或特性膏药） |
| 要求为 31 的某项个体值 | 在 100 级（第七、八世代）或 50 级（第九世代）进行极限特训 |
| 形态 | 对玩家可以改变形态的种类进行设置，例如洛托姆的家电形态 |

携带物品、精灵球、亲密度和努力值在生成后设置。第三或第四世代中，努力值超过 100 只有在宝可梦自相遇以来获得过经验值时才合法，因此这类记录会获得一点经验值，且不达到下一级。传说 阿尔宙斯的奋斗等级等于存储值加上由个体值决定的偏移量（从 20 起为 1，从 26 起为 2，31 时为 3）；存储值超过 10 减去偏移量就不合法，因此请求值会视为游戏显示的等级，并减去偏移量后存储。

亲密度属于初训家，范围为 0 到 255；编辑存档时会按生成值写入。主机通过交换接收宝可梦时，只有其玩家是初训家才会保留这一数值，因此“设置”中的“你的训练家”必须与该玩家一致（[你的训练家](gui.md#your-trainer)）。对于活动宝可梦，例如晶灿钻石中的玛纳霏，PKHeX 不接受不同于活动原设定的亲密度。

| 游戏 | 接收宝可梦的亲密度 |
| --- | --- |
| 火红、叶绿 | 每只非蛋宝可梦都设为 70，与训练家身份无关 [trade_scene.c:1071] |
| 传说 Z-A | 玩家的性别、ID 和姓名均与初训家一致时保留；否则玩家成为经手训练家，亲密度设为该种类的基础亲密度（[接收的记录](za.md#what-the-trade-writes-into-a-received-record)) |
| 晶灿钻石 | 回到初训家手中时保留；由另一训练家接收时，经手训练家亲密度为 50（[接收的宝可梦](bdsp_trade.md#what-the-console-does-to-a-received-pokemon)) |
| 传说 阿尔宙斯、朱 | 由另一训练家接收时，经手训练家亲密度为 50（[传说 阿尔宙斯](pla.md#what-a-trade-rewrites), [朱](sv.md#what-a-trade-rewrites)) |
| 剑 | 以接收玩家的姓名、ID 和性别生成并以 255 亲密度发送的皮丘，在下次升级时进化；若使用另一位训练家的身份生成，则不会进化 |
| Let's Go | 尚未测量 |

记录必须满足全部要求并通过合法性分析。保留首个满足条件的遭遇；若没有遭遇能够满足要求，拒绝原因会指出首个无法满足的要求。

提供的选项都是该种类在对应游戏中能够拥有的属性：

| 选项 | 列出条件 |
| --- | --- |
| 精灵球 | PKHeX 至少允许该种类的一种遭遇使用它 |
| 特性 | 存在带有该特性的合法生成结果；传说 Z-A 不列出任何特性 |
| 携带物品 | PKHeX 将其列为该游戏中已发布的可携带物品；Let's Go 和传说 阿尔宙斯没有携带物品 |
| 努力相关数值 | 努力值每项上限 252、合计上限 510；Let's Go 的觉醒值每项上限 200；传说 阿尔宙斯的奋斗等级每项上限 10 |

每款游戏抽样 25 个种类，分别使用每种列出的精灵球、每种性格、固定个体值组合、固定努力值、各性别以及一种携带物品生成，8095 次生成中有 8088 次合法。PKHeX 不接受剑／盾活动时拉比的勤奋、坦率和害羞性格，也不接受传说 Z-A 礼物美录梅塔的上述三种性格及浮躁性格。

在零售版剑中，用自定义选项生成一只宝可梦，并在队列中的下一次交换将其换回后，保存的记录与提供的交换记录一致（[提供的交换记录](swsh_trade.md#the-offered-record)）。在零售版晶灿钻石和朱中，一只带有指定昵称、性格、隐藏特性、性别、携带物品、精灵球、四个招式、个体值和努力值的 37 级异色皮卡丘，其概况界面显示了全部指定选项；晶灿钻石中换回的记录在十二个字段上均一致。

### Showdown 配置

“导入粘贴内容”使用 PKHeX 自身的解析器读取 Pokémon Showdown、Smogon 或 PKHeX 配置（`ShowdownParsing.GetShowdownSets`），并填充生成表单；随后点击“生成”来创建记录。解析器支持 PKHeX 能导出的任意语言配置（英语、法语、德语、意大利语、西班牙语、日语、韩语、中文）；手动输入且不符合 PKHeX 自身拼写的词项，例如把`Nature Rigide`用于表示`Nature : Rigide`，会导致该行无法解析。队伍导出内容的`=== [gen9] Team ===`头部会被跳过。文本遵循 Showdown 的默认值：没有`Level:`行表示等级为 100，`IVs:`行中省略的个体值为 31。解析器按 PKHeX 的顺序保留能力值，速度排在第四位。

| 配置中指定的内容 | 结果 |
| --- | --- |
| 解析器无法读取的行、游戏中不存在的种类或形态、该种类没有的特性、游戏不允许携带的物品、游戏中不存在的招式、总和超过 510 的努力值 | 拒绝并说明原因；不填充任何内容 |
| 太晶属性、超极巨化、极巨化等级、觉醒力量属性 | 忽略该项后填充，并附上说明 |
| 没有`Friendship:`行 | 使用遭遇自身的亲密度；Showdown 会省略其默认值 255，因此只有明确写出亲密度时，配置才会提出这一要求 |
| Let's Go 或传说 阿尔宙斯中的努力值、传说 Z-A 中的特性 | 省略，并附上说明 |
| 在交换队列中粘贴多份配置 | 从粘贴目标选择器开始，按顺序为每次交换填入配置：优先复用其后未修改的选择器，否则插入新选择器，直到达到队列上限；无法容纳的配置数量会在说明中列出。任何一份配置被拒绝，都会导致整次粘贴被拒绝 |
| 在队列以外粘贴多份配置 | 用第一份填充表单，并附上说明 |

剑／盾神秘礼物会验证 WC8 封印，并用 PKHeX 检查受支持的种类、形态、招式和安全物品。自定义 WC8 卡片属于分发内容，这种结构检查并不会使它们成为官方活动。可选的`--image`研究检查使用用户提供的游戏二进制文件；分发卡片不需要进行该检查。

### Let's Go 连接密码

Let's Go 主机端的密码由三个槽位组成。点击槽位会打开主机上的十种可选宝可梦，排列与主机一致，为两行、每行五个；每个精灵图下方显示名称，因此即使精灵图未下载，也仍能识别。选择后会填入当前槽位，并打开下一个空槽位。其值为三个用逗号分隔的英文名称，与`--code`接收的形式一致；只有三个槽位全部设置后才能开始：若有空槽位，启动器会使用默认密码建立主机端，而主机搜索永远找不到它。

### 交换队列

入口点支持在一次连接中完成多次交换的工具，最多接受六只宝可梦；“添加交换”会增加一个选择器，会话按顺序提供它们，每完成一次交换就使用一只。选择器会转换成重复出现的交换提供参数：

| 工具 | 提供方式 | 最后一次之后 |
| --- | --- | --- |
| 火红／叶绿主机端和加入端 | 同行宝可梦文件，`--trades N`，槽位为 0 到 N-1 | 主机端拒绝继续交换（`PLAYER_CANCEL_TRADE`），并等待玩家选择“取消”和“是”；加入端则取消并离开 |
| Let's Go 主机端 | `--offer`，然后使用`--next-offer`进行每次后续交换 | 启动器回答不再交换（`pokeldn/lgpe/trade.py`）；玩家返回退出 |
| Let's Go 加入端 | `--offer`，可重复指定 | 启动器回答不再交换；玩家返回退出 |
| 晶灿钻石／明亮珍珠主机端和加入端 | `--offer` / `--trade-template`，可重复指定 | 再次提供最后一只 |
| 传说 阿尔宙斯主机端和加入端 | `--trade-box-record` / `--offer`，可重复指定；加入端将列表交给主机端角色 | 再次提供最后一只 |
| 朱／紫主机端和加入端 | `--trade-offer`，可重复指定 | 启动器的交换阶段回答不再发送消息（`pokeldn/sv/trade.py`, `done`) |
| 剑／盾主机端和加入端 | `--offer-file`，可重复指定；后续每次交换均在同一会话中从盒子开始执行 | 再次提供最后一只 |
| 传说 Z-A 主机端和加入端 | `--trade-offer`，可重复指定；每次交换开始时预览新的记录 | 再次提供最后一只，并通过以下选项使用新的 PID：`--fresh-pid` |

每个交换启动器都会调用`pokeldn.ldn.show_done()`，每完成一次交换调用一次，调用位置为上表中该游戏流程的终点；它会让开发板的 LED 闪烁，并打印`[done] trade N complete`。“会话”面板的“正在提供”条带会统计这行输出，将队列中的前 N 只宝可梦标记为已交换。“已接收”列表不能替代它：部分启动器在主机选定宝可梦时就写入其记录，此时交换尚未完成。

`--fresh-pid`会为队列中每条记录分配独立的 PID 和加密常量。对于第 N 次交换（N 大于 1），接收内容会写入输出路径，并在扩展名前添加`-N`（火红／叶绿：`_tradeN_`和种类；朱／紫：`.N`，按不同的提供记录计数；晶灿钻石／明亮珍珠主机端：`_N`；传说 Z-A 和剑／盾：`-N`).

### 结束运行

主机完成交换后离开时，交换运行会自行结束，因此会话成功后无需点击应用的“停止”。

| 角色 | 结束条件 |
| --- | --- |
| 主机端，所有游戏 | 至少完成一次交换后，主机离开网络（`pokeldn.ldn.left_after_trade`）；若主机在尚未交换时离开，之后可能重新加入，因此主机端会继续运行 |
| 火红／叶绿主机端 | 主机离开网络，无论是否完成过交换 |
| 加入端 | 主机上的主机端关闭网络或移交角色（火红／叶绿、Let's Go、剑／盾、晶灿钻石／明亮珍珠）；朱／紫、传说 阿尔宙斯和传说 Z-A 在一次连接未完成任何交换后会重新搜索，若已完成交换则关闭 |

时间限制（`--seconds`, `--hold`）仍会约束主机始终不离开的运行。

离开行为的测量结果及未解问题，见各游戏的“离开”章节。

## 本地文件与发行版

`config/host.toml`和运行时参考消息纳入版本控制。`host.local.toml`、密钥、笔记、日志、研究镜像及生成的构建产物保留在本地。比较 ROM 校验和时，必须明确提供`--sum-reference`文件。正式运行的默认配置不会读取`scratchpad/`或本地反编译项目。

设置和已准备的交换宝可梦存放在平台的应用数据文件夹中。`POKELDN_DATA`可覆盖该位置，以便进行隔离运行。接收的记录使用`.pk3`, `.pb7`, `.pk8`, `.pb8`, `.pa8`, `.pk9`或`.pa9`.

“设置”通过以下入口提供手动清理功能：`pokeldn.app.storage` ([本地存储](gui.md#local-storage)）。扫描会列出可回收文件；删除以该清单为依据，重新检查当前选择，并保留已经发生变化的文件。清理期间应用保持忙碌状态，因此删除过程中不能启动会话或刷写固件。

打包器收集纳入版本控制的运行时文件、已发布的自包含 PKHeX 可执行文件，以及 ESP32、ESP32-S3、ESP32-C3 和 ESP32-C6 的合并无线固件。缺少任意镜像都会终止构建。机器配置和笔记不包含在内。Windows 构建会保留标准输入和输出，用于子进程日志及停止处理，同时隐藏所创建的控制台。PyInstaller 的窗口模式会在 Windows 上移除这些流。Linux 压缩包包含便携式可执行文件；带有构建机器路径的桌面条目会被省略。

## 验证

```
pip install -r requirements-dev.txt
dotnet build -c Release services/pkhex -warnaserror
python -m pytest tests/ -q -W error -n auto --dist worksteal
```

CI 在 Linux、macOS 和 Windows 上运行这些检查。私有研究测试资料是可选的；干净检出的代码无需它们，也能测试随附的参考数据和共享 PKHeX 服务。

发行版构建会针对冻结后的可执行文件运行`scripts/check_app.py`：检查 GUI 导入、全部启动器、七种 PKHeX 格式、串口发现及 esptool。此检查不需要密钥或连接开发板。
